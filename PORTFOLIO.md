## 🇬🇧 EN — long form

**OmniPost — AI Content Repurposing Pipeline**

**Role:** Solo developer · TypeScript / Node.js · Agentic LLM systems

**Problem.** Small businesses and creators sit on one valuable long-form asset — a blog post, a podcast episode, a webinar transcript — and then spend hours reformatting it into a tweet thread, a LinkedIn post, an Instagram caption and a newsletter blurb every single time. Existing AI tooling either dumps cliché-heavy posts that ignore brand voice, or quietly produces tweets that overflow 280 characters and hashtag piles that nobody dedupes.

**Solution.** An agentic TypeScript pipeline with a deliberate split of responsibility: **the LLM only writes drafts; code enforces every hard constraint.** Character limits, thread numbering, hashtag deduplication, platform-specific markdown stripping and slot-based scheduling all live in pure code (`enforce.ts`, `schedule.ts`) — the same pattern PulseReport uses for numbers. The LLM is asked only to write good prose in the configured brand voice; everything that must be exact is owned by the type system.

**Stack.** TypeScript 5.6 (strict, ESM), Node.js 20, Anthropic SDK with tool-use + prompt caching, OpenAI SDK pointed at Groq's OpenAI-compatible endpoint, zod for runtime validation, native `fetch` with a small HTML article extractor, hand-rolled RFC-5545 `.ics` generator, GitHub Actions CI.

**Pipeline.** `ingest(file | URL) → repurpose (Claude tool-use | Groq json_object) → zod schema → enforceConstraints → schedule (slot planner) → write JSON + Markdown + CSV + .ics`. Source-hash cache by `sha256(source + brand voice)` skips the LLM on repeat input. Deterministic fallback (paragraph splitter) handles any failure path.

**Engineering highlights.**
- LLM drafts; code enforces — tweets are split at sentence boundaries then numbered `1/n`, hashtags normalized + deduped + capped, captions clamped per platform.
- Claude path uses `tools` + `tool_choice` + `input_schema`; Groq path uses `response_format: json_object`. Both validated through the same zod schema.
- System prompt is `cache_control: ephemeral` — re-runs reuse the prefix.
- Graceful fallback: any LLM failure or schema mismatch falls through to a deterministic generator and is marked `degraded: true`. The pipeline never silently breaks.
- Brand voice (tone, audience, CTA, do/don't list, language) is part of the cache key — change the voice and the next run regenerates.
- `--mock` runs the entire pipeline offline using the seeded cache — what CI and the live-demo page both consume.
- RFC-5545 `.ics` generation in ~50 lines, zero dependencies — drag the output into Google Calendar.
- Plug-and-play source adapters behind one `ContentSource` interface — YouTube transcripts, RSS, Notion are one class each.
- Typed environment: zod parses `process.env` once at boot, invalid configuration fails fast.

**Outcome.** Production-ready open-source codebase. The live-demo page on GitHub Pages renders a real bundle (X thread, LinkedIn, Instagram, newsletter, pull quotes, 7-day calendar) with zero backend, generated by `npm run gen:demo`.
